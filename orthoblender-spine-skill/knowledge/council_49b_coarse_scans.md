# Council Investigation — #49b: committed library pressure still staircases on COARSE scans; whole-mesh Smooth "has no effect" on the region

2026-08-15. Follow-up to #49 (DEC-0045/0046) triggered by orthotist screenshots:
a library pressure on a coarse patient scan shows terraced shelves after commit,
and "Smooth (whole mesh)" visibly does nothing to that area (ZBrush-style local
smoothness is the stated goal).

## Repository Evidence

1. `rigo_brace/operators/region_ops.py` `_refine_footprint`: the split criterion
   is `predicted > max(1.4 * h_req, floor)` with `floor = 1.1 * mean_edge` —
   the refinement never splits below 1.1× the scan's OWN mean edge. On a coarse
   scan (user screenshot: region spans ~15 faces) the floor exceeds the sampling
   requirement, so the wall stays at scan density: the staircase #49 fixed on
   normal-density scans survives verbatim on coarse ones. Measured in the green
   battery itself: `[import_decim030] max_edge=21.51mm wall_viol=0` — a 21.5 mm
   wall edge in a committed footprint sailed through.
2. `tools/regionqualtest.py` wall-sampling oracle uses the SAME floor
   (`bound = max(1.4*h_req, 1.1*mean_pre_mm)`), so the oracle is blind exactly
   where production is broken — coarse meshes get a structural pass.
3. `rigo_brace/operators/region_ops.py` `_sync_preview`: a live (uncommitted)
   region is a DISPLACE modifier (vertex group, NORMAL) on the scan.
   `rigo_brace/operators/mesh_ops.py` `rigo.smooth` appends a SMOOTH modifier
   AFTER those previews and applies it (Blender logs "Applied modifier was not
   first" — visible in our own test logs): the base smooths, then the preview
   re-displaces per-vertex at coarse density every frame. The region's shape is
   generated by the modifier and is immune to smoothing — "no effect" is the
   mechanically correct observation.

## Independent Findings

### mario-botsch
The `1.1 × mean_edge` floor makes the input triangulation the CEILING of output
quality — the tool's behavior is a function of how the same body happened to be
triangulated, the exact property a density-robust tool must not have. The
sampling requirement h_req(g) is already absolute (mm, from amount and turning);
the floor adds nothing on dense meshes (there `predicted ≤ 1.4·h_req` self-
limits: dense grid fixture 2 mm edges, requirement 8.75 mm — no-op with or
without the floor) and destroys the tool on coarse meshes. Fix: delete the
floor; the criterion is `predicted > 1.4 · h_req(g)`, period.

### geometry-reliability
The oracle inherited the floor, so the defect class was invisible to the green
battery: decim030's 21.5 mm wall edge measured wall_viol=0. Oracle must drop
its mean-edge floor in the same patch (contract formula change), and a coarser
fixture than decim030 must join the battery (the user's scan is coarser).
A fix that production and oracle share by formula is acceptable because they
compute it from independent inputs (pre-commit snapshot vs live BMesh), as with
the osc bound.

### campbell-barton
`rigo.smooth` on a scan carrying live DISPLACE previews applies a non-first
modifier — defined result (smooths base) but Blender itself warns, and the
user-visible outcome is "nothing happened" because the previews redraw on top.
Do NOT silently reorder or apply the previews (clinical intent is uncommitted).
Minimal safe change: move the smooth modifier to index 0 before applying
(silences the order warning, same base-smoothing semantics) and report a
WARNING naming the live previews when they exist, telling the orthotist the
smoothed result is underneath them. No veto on the refinement change.

### ryan-schmidt (cross-review)
The DISPLACE preview shows a staircase the commit will no longer produce —
a preview-fidelity gap, now larger post-fix. Acceptable for this patch
(preview is explicitly a preview; commit is the product) but record as an open
enhancement: preview via subdivided/evaluated geometry when density demands.

### manuel-rigo (governor)
Amount, feather, footprint, pairing, provenance unchanged; refinement is mesh
sampling only, already approved at commit in #49. Extending it to coarse scans
is the same clinical semantics. NO VETO.

## Root Cause

One falsifiable sentence: the refinement split floor (and its oracle mirror)
is proportional to the scan's own mean edge length, so on coarse scans the
sampling requirement is never enforced and the pre-#49 staircase ships —
while the smooth-tool observation is a separate, correct consequence of live
DISPLACE previews regenerating displacement on top of the smoothed base.

## Council Verdict

**HARDEN** (two minimal changes + one fixture), unanimous, no vetoes.

## Minimal Safe Change

1. `_refine_footprint`: delete the mean-edge floor from the split test.
2. Oracle/contract: delete `1.1·mean_edge` from the wall-sampling bound.
3. `rigo.smooth`: move modifier first before apply; WARNING when live region
   previews exist on the scan.
4. Battery: add a coarse import fixture (decimate 0.15 ≈ the screenshot's
   density) gated refined + wall-clean; re-measure all populations.

## Regression Tests (fail before the patch)

- Dense no-op gates must stay green (floor removal must not disturb them).
